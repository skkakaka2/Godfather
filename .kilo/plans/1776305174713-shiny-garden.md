# Family Hub 技术底座实施计划

> 目标：从零搭建 Spring Boot 3 企业级项目骨架，包含所有公共基础设施

## 六、种子数据注入

### 方案：ApplicationRunner

创建 `com.family.hub.config.DataInitializer` 实现 `ApplicationRunner`，在应用启动时检查并插入种子数据。

**执行逻辑**：
1. 检查 `user` 表是否有 ADMIN 角色用户
2. 如果没有，创建默认家庭 + 管理员账户
3. 使用 `PasswordEncoder` 加密密码
4. 密码从配置文件读取，支持环境变量覆盖

**配置项**（application.yml）：
```yaml
app:
  seed:
    admin-username: ${ADMIN_USERNAME:admin}
    admin-password: ${ADMIN_PASSWORD:admin123}
    family-name: ${FAMILY_NAME:我的家庭}
```

**实现文件**：
- `config/DataInitializer.java`

**幂等性保证**：
- 先查再插（SELECT COUNT WHERE role='ADMIN'）
- 不使用 saveOrUpdate，避免覆盖已有数据

完成技术底座后，按优先级依次开发业务模块：
1. **Phase 1**：任务打卡（模块 B）
2. **Phase 2**：积分商城（模块 C）
3. **Phase 3**：成长时光机（模块 E）
4. **Phase 4**：口算特训（模块 A）
5. **Phase 5**：家庭日历（模块 F）+ 阅读书房（模块 D）

## 七、模块 B 表结构设计：任务打卡

### 表总览

共 3 张表：`task_template`、`daily_task`、`task_checkin`

### ER 关系

```
family ──┬── user
         │
         ├── task_template (模板，属于 family)
         │       │
         │       └──→ daily_task (每日任务实例，属于 user)
         │                   │
         │                   └──→ task_checkin (打卡记录)
         │
         └── [临时任务也生成 daily_task，template_id 为 NULL]
```

### DDL

#### 1. task_template（任务模板）

家长创建的可复用任务模板。

```sql
CREATE TABLE task_template (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    family_id       BIGINT          NOT NULL COMMENT '所属家庭',
    name            VARCHAR(64)     NOT NULL COMMENT '模板名称',
    category        VARCHAR(16)     NOT NULL COMMENT 'STUDY/SPORT/CHORE/HOBBY/OTHER',
    icon            VARCHAR(32)     NULL     COMMENT '图标标识',
    default_points  INT             NOT NULL DEFAULT 0 COMMENT '默认积分数',
    applicable_sun  TINYINT(1)      NOT NULL DEFAULT 0 COMMENT '周日是否适用',
    applicable_mon  TINYINT(1)      NOT NULL DEFAULT 1 COMMENT '周一是否适用',
    applicable_tue  TINYINT(1)      NOT NULL DEFAULT 1 COMMENT '周二是否适用',
    applicable_wed  TINYINT(1)      NOT NULL DEFAULT 1 COMMENT '周三是否适用',
    applicable_thu  TINYINT(1)      NOT NULL DEFAULT 1 COMMENT '周四是否适用',
    applicable_fri  TINYINT(1)      NOT NULL DEFAULT 1 COMMENT '周五是否适用',
    applicable_sat  TINYINT(1)      NOT NULL DEFAULT 0 COMMENT '周六是否适用',
    deadline_time   TIME            NULL     COMMENT '默认截止时间，如 21:00:00',
    sort_order      INT             NOT NULL DEFAULT 0 COMMENT '排序',
    enabled         TINYINT(1)      NOT NULL DEFAULT 1 COMMENT '是否启用',
    created_at      DATETIME        DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted         TINYINT(1)      DEFAULT 0,

    INDEX idx_family_enabled (family_id, enabled)
) COMMENT '任务模板';
```

#### 2. daily_task（每日任务）

每天根据模板自动生成 + 家长手动添加的临时任务。一条记录 = 一个孩子的一天的一项任务。

```sql
CREATE TABLE daily_task (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    family_id       BIGINT          NOT NULL COMMENT '所属家庭',
    user_id         BIGINT          NOT NULL COMMENT '分配给哪个孩子',
    template_id     BIGINT          NULL     COMMENT '关联模板ID，临时任务为NULL',
    task_date       DATE            NOT NULL COMMENT '任务日期',
    name            VARCHAR(64)     NOT NULL COMMENT '任务名称（冗余快照）',
    category        VARCHAR(16)     NOT NULL COMMENT '分类',
    icon            VARCHAR(32)     NULL     COMMENT '图标',
    points          INT             NOT NULL DEFAULT 0 COMMENT '完成可得积分',
    deadline_time   TIME            NULL     COMMENT '截止时间（可覆盖模板默认值）',
    sort_order      INT             NOT NULL DEFAULT 0 COMMENT '排序',
    status          VARCHAR(16)     NOT NULL DEFAULT 'PENDING' COMMENT 'PENDING/COMPLETED/CONFIRMED/REJECTED/SETTLED',
    is_temp         TINYINT(1)      NOT NULL DEFAULT 0 COMMENT '是否临时任务',
    reminded        TINYINT(1)      DEFAULT 0 COMMENT '是否已发送超时提醒',
    created_at      DATETIME        DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted         TINYINT(1)      DEFAULT 0,

    INDEX idx_user_date (user_id, task_date),
    INDEX idx_family_date (family_id, task_date),
    INDEX idx_template (template_id)
) COMMENT '每日任务';
```

**状态流转**：
```
PENDING → COMPLETED → CONFIRMED → SETTLED
                   ↘ REJECTED → (可重新打卡 → COMPLETED)
```

#### 3. task_checkin（打卡/确认记录）

每次打卡、确认、打回的操作记录。

```sql
CREATE TABLE task_checkin (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    daily_task_id   BIGINT          NOT NULL COMMENT '关联每日任务',
    user_id         BIGINT          NOT NULL COMMENT '操作人',
    action          VARCHAR(16)     NOT NULL COMMENT 'CHECKIN/CONFIRM/REJECT',
    photo_url       VARCHAR(512)    NULL     COMMENT '照片凭证URL',
    remark          VARCHAR(500)    NULL     COMMENT '备注',
    created_at      DATETIME        DEFAULT CURRENT_TIMESTAMP,
    deleted         TINYINT(1)      DEFAULT 0,

    INDEX idx_task (daily_task_id)
) COMMENT '打卡/确认记录';
```

### 设计决策

| 决策 | 理由 |
|------|------|
| 7 个布尔字段存适用日期 | 查询直观 `WHERE applicable_mon = 1`，无需解析 |
| `deadline_time` 用 TIME 类型 | 只存时刻（21:00），日期由 `task_date` 决定 |
| `daily_task` 冗余 name/category/icon | 模板修改后不影响历史任务，数据自包含 |
| `is_temp` 标记临时任务 | 临时任务无 template_id，需字段区分 |
| `status` 用 VARCHAR | 可读性优先，枚举值少，家庭场景无性能瓶颈 |
| 打卡记录与每日任务分离 | 任务可能被打卡→打回→重新打卡，需完整历史 |
| `task_checkin.action` 统一记录 | CHECKIN/CONFIRM/REJECT 都在此表，追踪完整操作链 |
