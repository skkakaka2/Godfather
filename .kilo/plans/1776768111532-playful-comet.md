# 每日任务自动生成实现方案

## 现状分析

**已具备：**
- 数据库表：`task_template`（任务模板）、`daily_task`（每日任务）
- 定时任务线程池配置：`SchedulingConfig.java`（4线程）
- 任务模板 CRUD：`TaskTemplateService.java`
- 用户实体：`User.role` 字段区分角色（ADMIN/MEMBER/GUEST）

**待实现：**
- DailyTaskMapper 和 DailyTaskService
- 定时任务调度器（`@Scheduled`）
- 每日任务自动生成逻辑

---

## 实现方案

### 1. 核心组件

| 组件 | 说明 |
|------|------|
| `DailyTaskMapper` | MyBatis-Plus Mapper 接口 |
| `DailyTaskService` | 业务服务：创建任务、查询任务 |
| `DailyTaskScheduler` | 定时任务类，包含自动生成逻辑 |

### 2. 定时任务生成逻辑

```
每天凌晨执行：
1. 获取所有家庭列表
2. 对每个家庭：
   a. 查询该家庭所有 MEMBER 角色用户（孩子）
   b. 查询该家庭所有启用的任务模板
   c. 根据今天星期筛选适用的模板
   d. 对每个孩子 + 每个适用模板：
      - 检查是否已生成（防重复）
      - 创建 daily_task 记录（冗余模板的 name/category/icon/points）
```

### 3. 关键设计决策（已确认）

| 决策点 | 方案 |
|--------|------|
| 执行时间 | **凌晨 06:00**（cron: `0 0 6 * * ?`） |
| 手动触发 | **需要**提供 API 接口，家长可指定日期生成任务 |
| 幂等性 | 插入前检查 `user_id + template_id + task_date` 是否已存在 |
| 配置方式 | cron 表达式通过 `@Value` 从配置文件读取 |
| 跨家庭处理 | 遍历所有家庭，每个家庭独立处理 |
| 只给孩子生成 | 只为 `role = 'MEMBER'` 的用户生成任务 |

### 5. 实现步骤

**步骤 1**：创建 DailyTaskMapper
```java
@Mapper
public interface DailyTaskMapper extends BaseMapper<DailyTaskEntity> {
}
```

**步骤 2**：创建 DailyTaskService 接口
```java
public interface DailyTaskService {
    void generateDailyTasks(LocalDate date);
    void generateDailyTasksForFamily(Long familyId, LocalDate date);
}
```

**步骤 3**：实现 DailyTaskServiceImpl
- 核心逻辑：遍历家庭 → 获取孩子 → 获取适用模板 → 创建任务
- 幂等性检查：查询是否已存在相同记录
- 冗余字段：从模板复制 name/category/icon/points 到 daily_task

**步骤 4**：创建 DailyTaskScheduler 定时任务
```java
@Scheduled(cron = "${app.task.generate-cron}")
public void generateDailyTasks() {
    dailyTaskService.generateDailyTasks(LocalDate.now());
}
```

**步骤 5**：添加手动生成 API
```java
@PostMapping("/api/v1/tasks/generate")
public R<Void> generateTasks(@RequestParam LocalDate date) {
    dailyTaskService.generateDailyTasks(date);
    return R.ok();
}
```

**步骤 6**：更新 application.yml 配置
```yaml
app:
  task:
    generate-cron: 0 0 6 * * ?
```
